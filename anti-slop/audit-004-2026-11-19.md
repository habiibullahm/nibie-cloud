# Anti-slop audit 004: dashboard user flow, Instances and payment (2026-11-19)

Mode AFTER. Scope: the customer flow the owner showed on the Instances screen (two expired purchases "aaa" and
"habib32" above one active instance): Instances list, Deploy, payment return, first visit to an instance.
Files read: `apps/web/src/app/(app)/instances/instances-view.tsx`, `deploy/deploy-form.tsx`,
`instances/[id]/instance-frame.tsx`, `instances/[id]/page.tsx`, `components/app/app-shell.tsx`, `lib/billing.ts`,
backend `src/modules/billing/billing-service.ts` (checkout) and `billing-tick.ts` (expiry). Skill read: core.
Priority: Tinggi = Hard Gate, Sedang = Purpose-Gate, Rendah = Quality Lock. Nothing is changed until the owner picks numbers.
Earlier dashboard findings stay in audit 002 (D1 to D24); this list does not repeat them.

Note: the working tree already has an uncommitted change to `evaluateReturn` in `apps/web/src/lib/billing.ts` (judge only
the newest invoice, so old expired purchases no longer turn a successful payment into "failed"). It is related to F1 to F3
but was not written in this audit and is not verified here.
