# Anti-slop audit 003: usage-meter mod (2026-11-18)

Mode AFTER. Scope: the `usage-meter` Claude Code mod (outside this repository, in this session's mods folder:
`hooks/register.ts`, `.claude-plugin/plugin.json`), as the owner saw it in the status line
(`today 0/20% wk · 5h 57% · 7d 41% · $2.24`). Everything the mod shows people is text: the status line, toasts, the
reason a blocked prompt is refused, and the `/usage-meter` output. Skills read: core, copywriting.
Priority: Tinggi = Hard Gate, Sedang = Purpose-Gate, Rendah = Quality Lock. Nothing is changed until the owner picks numbers.

## Findings

| # | Prio | Where | Problem | Fix |
|---|---|---|---|---|
| M1 | Tinggi (R-38, C-5) | register.ts:41-46, 76-85 | "today 0/20%" counts only from the mod's first reading of the day, but reads as the whole day. The screenshot shows 0% today in a session that had already cost $2.24 before the mod loaded. The first turn of every new day is also not counted. | Until the mod has watched a day from its start, label the figure honestly, e.g. `since 14:05: 0/20% of week` |
| M2 | Tinggi (R-27) | register.ts:50-58, 87-96, 123 | States are missing from the status line. Before the first reading it shows only `$0.00` or nothing, with no "waiting for first reply". When the budget is used up (blocked, overridden, or past budget in warn mode) the status line looks the same as normal, so the state lives only in a toast that disappears. If the prompt guard itself fails it lets prompts through without saying so. | Status text for each state: `waiting for first reading`, `blocked: 21/20% today`, `over budget (override)`; a one-time notice when the guard fails |
| M3 | Tinggi (R-02) | register.ts:134-137 | `/usage-meter` shows machine values to people: `seven_day`, `five_hour`, a raw UTC timestamp (`resets 2026-11-20T03:00:00Z`), `no cost ledger`, `Mode: block`. | Plain words and local time: `Weekly limit: 41%, resets Thu 20 Nov 10:00` |
| M4 | Tinggi (R-35) | whole mod | Verified by validate, type-check and 6 tests only. `/usage-meter`, `/usage-meter override` and a real blocked prompt have not been run in a live session. | Run each once in a live session and record what happened |

## Checked and not flagged

- No em dashes, buzzwords, or fabricated figures: every number comes from the engine (`session.measure`, `$.session.usage()`).
- The cost toast gives a specific next step (`/compact` or a fresh session), not a generic CTA.
- State is not conveyed by color: the mod draws text only. Contrast and color of the status line are the engine's, not the mod's.
- Purpose-Gate techniques (gradients, glow, icons, badges, motion) do not occur, so there are no Sedang findings.
